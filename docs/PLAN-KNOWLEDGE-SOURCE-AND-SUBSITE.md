## 一、前置决策与其红利

### 1.1 决策

| 项 | 上一版约束 | 本轮决策 | 影响 |
|---|---|---|---|
| `file://` 直开 | 硬红线 | **放弃** | 可用 ESM / `fetch()` / 构建 / Worker / IndexedDB / 真实静态站生成 |
| 运行时零依赖 | 硬红线 | **保留**（产物仍是纯静态） | 构建期可自由引入依赖，产物零外部请求 |
| 纯文字出处、零外链 | 硬红线 | **保留** | 每条内容有可核查的纯文字引用，正文不嵌外链 |
| 零遥测 / 纪录仅本地 | 硬红线 | **保留** | 分站不引入后端、统计、账号 |

### 1.2 放弃 `file://` 换来的 6 项能力（旧架构做不到）

1. **ESM + `fetch()` JSON** —— 知识数据按需分片加载，实体页不必带全量数据
2. **真正的构建期** —— esbuild 打包、压缩、tree-shaking、代码分割
3. **Web Worker** —— 全文索引构建与查询移出主线程，不卡首屏
4. **IndexedDB** —— 索引与图谱数据本地缓存，第二次访问近乎瞬时
5. **增量构建** —— 改一个实体只重建受影响页面（内容哈希缓存）
6. **现代 CSS** —— `:has()`、容器查询、级联层、`@layer`、嵌套——分站的组件化视觉不用再手写 hack

> 代价：双击 HTML 打不开。用户改用任意静态服务器 / GitHub Pages / `npx serve`。这与"分站要上线到子域名"的目标一致，**不构成实际损失**。

## 三、知识源之一：知识总目录与覆盖矩阵

> 这是本计划**最关键的机制**：「确保把所有相关知识全部收入」必须可核查、可追踪、可门禁，

### 3.1 知识总目录（`_meta/inventory/`）

### 3.2 清单条目 schema

```yaml
- id: affine
  title: 仿射密码
  title_en: Affine Cipher
  status: done              # done | todo | exempt
  priority: P1              # todo 必填（P0 必收 / P1 重要 / P2 补充）
  target: 2026-Q4           # todo 必填
  quality: tier1            # tier1 旗舰级 | tier2 标准级 | tier3 索引级
  domain: d02-monoalphabetic

  level: 2                  # 1 入门 / 2 进阶 / 3 专家 / 4 研究
  prereq: [caesar, substitution]

  threats: [CPA]

```

### 3.3 三档质量标准（决定工作量分配的关键）

| 档 | 内容要求 | 覆盖对象 | 单条成本 | 适用 |
|---|---|---|---|---|
| **tier1 旗舰级** | 三层深度全文（为什么重要 / 现实哪里用 / 怎么被破）+ ≥2 条权威出处 + 完整多轴标注 + 关联图谱 | 核心术语、关键人物、旗舰机器、著名密件 | 0.3–0.6 人日 | ≈ 380 条 |
| **tier2 标准级** | 摘要 + 1–2 条出处 + 全部轴标注 + 3–5 条关联 | 绝大多数实体 | 0.06–0.12 人日 | ≈ 1,200 条 |
| **tier3 索引级** | 名称 + 一句话定义 + 关联（作为导航占位，可随时升级） | 长尾 | 0.01–0.03 人日 | ≈ 300 条 |

> **门禁只卡"有没有"，不卡"写多好"**——质量用 tier 标注 + 抽样核证推进；
> 覆盖用 `status` 卡死。两者解耦，才能既全又深。

### 3.4 覆盖矩阵与门禁

生成物：
- `docs/coverage-matrix.md` —— 人可读的 19 时代 × 24 域热力表，格内显示 `done/tier1 / done/tier2 / todo`
- `build/coverage.json` —— 机器可读
- `build/gaps.json` —— 按 `priority × target` 排序的缺口队列（这就是**下一轮的工作清单**）

门禁 `check-inventory.js`：
- ❌ 任何 `status: todo` **缺 `priority` 或 `target`** → 失败
- ❌ 任何 `status: exempt` **缺 `note`** → 失败
- ❌ 实体 md 存在但**不在任何清单里** → 失败（防止"有货无账"）
- ❌ 清单条目 `status: done` 但**实体文件不存在** → 失败
- ❌ 同一 `id` 出现在两个清单 → 失败（id 全局唯一）
- ✅ 输出 `总条目 / 已收 / 缺口 / tier 分布`

### 4.2 实体模型升级（frontmatter v2）

现有 frontmatter 只有 `title/title_en/type/era/domain/game/sources`。v2 增补：

```yaml
---
title: 仿射密码
title_en: Affine Cipher
type: algorithm              # 新增类型：algorithm/standard/attack/theorem/event/tool/application
id: affine                   # 全局唯一规范 ID
aliases: [仿射密码, affine]  # 异译/旧名/英文别名
era: [e02-classical]         # 多值
domain: [d02-monoalphabetic]
subtopic: [monoalphabetic-substitution]
apps: [military, education]  # 应用场景轴
threats: [CPA, CCA]          # 威胁模型轴
level: 2                     # 难度
prereq: [caesar]             # 前置
layer: 3                     # IA 层级（1–6）
tier: tier1
status: done
quality: verified            # draft | verified
sources:
  - { title: "Affine cipher", author: "Wikipedia", kind: "reference" }
  - { title: "Cryptanalysis of the affine cipher", author: "…", kind: "paper" }
related: [caesar, atbash, substitution]
---

# 仿射密码（Affine Cipher）
> 一句话定位

## 是什么
## 为什么重要
## 现实哪里用
## 怎么被破
## 关联
## 出处
## English / 英文版
```

**关键设计**：
- `aliases` 支撑**多维检索**（用户搜"仿射"能命中，搜"affine"也能命中）
- `threats` / `apps` 支撑**多维筛选**（"按威胁模型浏览"）
- `level` / `prereq` / `layer` 支撑**多层次学习**
- `quality: draft|verified` 让"收全"与"核证"解耦

| **P3 机械时代** | 进阶 | 30 | 6 h | 转子结构→接线板→战时流程 |
| **P4 现代密码工程师** | 专业读者 | 64 | 12 h | 分组→流→哈希→AEAD→公钥→签名→协议 |
| **P5 前沿与后量子** | 研究者 | 38 | 8 h | 侧信道→零知识→MPC→量子→后量子→同态 |
| **P6 查证者** | 查证/写作 | 按需 | — | 按域纵深 + 全量出处溯源 |

每步 = 1 个实体 + 1 个"动手任务"（可读可查的最小练习：算一次、做一次、查一次）+ 前置依赖 + 预计时间。

**前置依赖 DAG** 由 frontmatter 的 `prereq` 自动生成，路径页与实体页共用。

### 5.6 检索

- 构建期生成 `build/search-index.json`（倒排 + 前缀索引 + 同义词 + 别名）
- 客户端 **Web Worker** 内建 + 查询；**IndexedDB** 缓存
- 支持：中文分词（bigram）+ 英文前缀 + 别名 + 拼音首字母（可选）
- 结果高亮 + 实体类型筛选 + "在 XX 视图中查看"

### 5.7 性能与离线

| 指标 | 目标 |
|---|---|
| 首页 LCP | < 1.5 s |
| 实体页 LCP | < 1.0 s |
| 搜索首次响应 | < 100 ms（Worker） |
| 单页 JS | < 300 KB（gzip，含 three.js 仅晶格视图按需加载） |
| 实体页 HTML | < 60 KB |
| 离线 | SW 预缓存外壳 + 最近访问实体；搜索索引按需缓存 |
| 无 JS 降级 | 实体页为**服务端静态 HTML**（无 JS 也能读全部正文） |

> **最后一条是硬要求**：知识站的正文不能依赖 JS。晶格/搜索是增强，不是前提。

## 六、技术选型（效率优先）

### 6.1 知识源仓

| 项 | 选择 | 理由 |
|---|---|---|
| 载体 | Markdown + YAML frontmatter | 人可读可审、diff 友好、Git 友好 |
| 清单 | YAML（`_meta/inventory/`） | 机器可读 + 人可维护 |
| 生成器 | **自研 Node 脚本**（延续 `tools/mdgen/`） | 延续既有模式；无模板语言阻抗 |
| 构建期依赖 | `js-yaml` `markdown-it` `esbuild` `sanitize-html` | 成熟稳定、构建期自由 |
| CI | GitHub Actions：gen-all → parity → inventory → sources → links → diff 检测 | 每次提交必跑 |

### 6.2 分站构建

| 项 | 选择 | 理由 |
|---|---|---|
| 静态生成器 | **自研 Node 生成器**（`tools/site/build.js`） | 内容是**结构化实体集合**而非 Markdown 博客流，自研可 1:1 映射数据模型、零模板阻抗、支持增量构建与按实体分片 |
| 不用 Hugo/Astro/Jekyll | — | 那些为"内容优先 + 主题模板"设计；此处需要"实体优先 + 多维图谱 + 自定义交互"，自研更省 |
| 客户端 | ESM + esbuild 打包 + Worker + IndexedDB | 性能与体验 |
| 样式 | 原生 CSS + `@layer` + 容器查询 + `:has()` | 零运行时依赖 |
| 3D 晶格 | three.js（本地 vendor，**按需加载**，仅晶格视图用） | 避免首屏为 3D 买单 |
| 输出 | 纯静态（HTML/CSS/JS/JSON） | GitHub Pages 直上 |

### 6.3 仓库与部署

| 仓 | 部署 | 说明 |
|---|---|---|
| `poyinet/cryptography-decode-history` | 不部署（源） | 知识源；也可开 Pages 只做"源码阅读" |
| `poyinet/crypto`（**新建**） | `crypto.poyi.net`（CNAME） | 分站产物仓；内容为编译产物，**由知识源仓 CI 自动推送** |
| `poyinet/www` | `poyi.net` | 主站（3D 游戏）——**本轮不动**，仅在接口层预留 |

**产物同步机制**：知识源仓 CI 跑 `gen-all` → 校验 → 生成 `build/site/**` → 推送到 `poyinet/crypto`（CI 内的 deploy key）。
**分站永不手改**——与主站"内容不手改"同一原则。
